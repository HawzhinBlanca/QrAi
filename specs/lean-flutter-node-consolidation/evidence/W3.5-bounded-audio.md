- The first W3.5 proof failed because the Node shadow closed every valid admitted socket 1013 and
  had no frame reader, queue, session ceiling, sequence cursor, acknowledgement sender, audio
  metrics, transport ceiling, or audio-aware shutdown path.
- The test-first proof used a deliberately paused object store to make slot, byte, ordering, and
  shutdown behavior deterministic. Real Fastify WebSockets separately proved application and

- Manual pre-commit review found that the first slow-consumer implementation checked only the

  retain a chunk whose acknowledgement has no bounded room.

## Implemented boundary

- `server/src/realtime/audio.mjs` owns one dependency-free, process-local runtime with immutable
  2 MiB application and 2 MiB + 64 KiB transport ceilings, 8 chunks/4 MiB per session, 64 MiB
  process-wide, 100 active/draining sessions, and 64 KiB projected acknowledgement buffering.
- Empty and oversized frames do not consume sequence; text remains ignored for Rust parity. One
  FIFO consumer per session advances sequence only after a successful bounded reservation, rejected
  frames reuse the cursor, and reconnect state is bounded to 1,024 entries/six hours in one process.
- `accepted=true` means enqueued, not stored or indexed. The consumer writes raw bytes through the
  existing create-only object-store interface with claims-derived identity/retention, fixed 16 kHz
  and 480 ms spans, and a two-second abort signal. Store success, failure, and abort remain separate
  fixed-cardinality outcomes.
- Fastify registers the explicit transport `maxPayload`, closes protocol errors generically, and
  drains or aborts audio before replay, object storage, and Postgres close. Late store settlement is
  caught and cannot restore accounting or create an unhandled rejection.
- No package, lockfile, schema, Compose service, image, port, broker, public route, traffic target,
  Rust, Web, Flutter, inference, ticket-wire, Quran-data, auth, or learner-feedback source changed.
  Rust remains the sole public realtime target and compatibility oracle.
