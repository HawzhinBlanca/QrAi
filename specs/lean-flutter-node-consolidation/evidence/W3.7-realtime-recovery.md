## Red-first and audit evidence

- The first recovery-policy tests failed because no language-neutral policy fixture or executable
  controller existed. The former chaos probe counted successful `send()` calls as delivery and
  could therefore report success without an acknowledgement.
- The first migration/finalization proof failed because sessions had no durable recovery report,
  the API had no strict report boundary, and responses could not distinguish complete, degraded,
  and legacy-unverified recordings.
- The first exact-invocation proof failed until the isolated recovery and migration suites were
  wired once, and only once, into canonical verification.
- Final source review found two authorization defects before commit: report validation happened
  before authentication, and staff who could perform legacy finalization could forge learner-side
  recovery truth. Red parity cases now prove anonymous hostile input receives 401 before shape
  validation and only the owning learner may create or retry a report. Existing staff finalization
  remains compatible only through the legacy empty body.
- The review also found a stale relocation guard that required the chaos probe to import ticket
  cryptography directly. It now proves the opposite boundary: every attempt obtains an API-issued
  ticket and neither the current nor retired ticket module is imported by the client probe.

## Implemented boundary

- A frozen v1 policy permits one in-flight raw-binary frame, a FIFO queue bounded by both 125
  chunks and 2 MiB, a fresh API ticket on every connection attempt, equal-jitter retries from
  500 ms to 15 seconds, and at most six retry decisions. Retry state resets only after an accepted
  acknowledgement, not after a transport opens.
- The v1 wire has no client idempotency key. A sent frame whose acknowledgement is unknown is
  therefore terminal and counted once as uncertain; it is never replayed. Rejected frames retain
  sequence identity, while overflow, malformed/foreign acknowledgements, device failure, and retry
  exhaustion stop capture and finalize exactly once.
- Additive migration 0038 stores one constrained, immutable, privacy-safe recovery summary on the
  existing forced-RLS session row. Authentication precedes exact-key parsing; the owning learner is
  the only report writer; the report is committed in the tenant transaction before job enqueue and
  participates in finalization idempotency.
- Finalization returns `recordingStatus` plus separate client-dropped, client-uncertain, and
  server-lost counts. It never fabricates a combined loss total because v1 cannot deduplicate a
  client-uncertain frame against a server accepted-loss identity. A legacy absent report is
  `unverified`, never `complete`.
- The chaos command uses the same proved controller, API-issued tickets, and acknowledgement
  accounting. Raw audio, tickets, nonce, identity, and arbitrary diagnostics do not enter reports,
  metrics, exceptions, snapshots, or job documents.
- No package, lockfile, runtime dependency, public route set, Compose edge, Rust gateway, Web
  runtime, Flutter runtime, ticket wire, or seven-field acknowledgement wire changed. Rust remains
  the public realtime traffic target.
