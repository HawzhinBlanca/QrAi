# W2.4 slice 5 evidence — relocate the transparent HTTP proxy

**Status:** engineering proof complete; W2.4 remains open for the remaining modules and remote CI<br>
**Date:** 2026-08-07

## Scope

- Moved `services/node-api/lib/proxy.mjs` to `server/src/lib/proxy.mjs` and removed the old owner.
- Updated the strangler catch-all plus all eleven route-level delegation consumers.
- Preserved the single `proxy` export and its request/response byte, header, status, redirect,
  repeated-cookie, empty-body, and hop-by-hop behavior.
- Changed no route ownership, traffic target, authentication policy, response schema, or canonical
  Quran data.

## Red-first and focused proof

The new ownership and all-caller guards failed in exactly two tests before the implementation. After
the move:

```text
node --test \
  tests/node-api/module-relocation.test.mjs \
  tests/node-api/shell.test.mjs \
  tests/node-api/production-image.test.mjs \
  tests/node-api/standalone-lifecycle.test.mjs
# tests 34
# pass 34
# fail 0

pnpm --filter @quran-ai/server build
# exit 0

rg 'services/node-api/lib/proxy\.mjs|from "\.\.?/lib/proxy\.mjs"' \
  services server tests scripts packages
# no stale references

git diff --check
# exit 0
```

The shell vectors specifically proved method/path/query/body forwarding, multiple independent
`Set-Cookie` headers, absence of an invented content type, non-JSON response bytes, upstream error
status, empty GET bodies, CORS behavior, preflight interception, and explicit route ownership.
