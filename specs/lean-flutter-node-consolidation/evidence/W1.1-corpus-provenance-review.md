# W1.1 canonical corpus provenance review

**Review date:** 2026-08-06<br>
**Scope:** source/provider/edition/licensing identity and source-id migration only<br>
**Arabic text decision:** preserve the shipped bytes exactly

## Finding

The repository acquired its complete canonical Arabic corpus directly from **Al Quran Cloud**, using
edition identifier **`quran-uthmani`**. The existing import manifest already records
`https://api.alquran.cloud/v1/surah`, and the importer stores each API `ayah.text` value directly.
The importer, manifest, and all 114 Surah files entered repository history together in commit
`d4bbdf5872510ef37c6fc64d7939621dbedaf0dd`; there is no earlier repository corpus from which to
infer another direct provider.

One later SQL generator incorrectly builds the full corpus with source id `tanzil`. That label is
not supported by the acquisition path and must not remain the database authority.

## Byte and edition verification

On 2026-08-06 the current Al Quran Cloud endpoint
`https://api.alquran.cloud/v1/quran/quran-uthmani` was compared in memory with all 6,236 shipped
ayah strings. All **6,236 of 6,236** strings were byte-identical. Both sides produced the existing
content SHA-256:

`7d47065915b6dc645f6f975cb0eb1ec3d8f121869e911de97c69700c3fb6df5f`

The response described the edition as identifier `quran-uthmani`, language `ar`, English name
`Uthmani`, format `text`, and type `quran`. This live comparison corroborates the checked-in import
evidence; it does not replace the repository's immutable checksum gate and is not run in tests.

## Provider terms and upstream limit

Primary sources reviewed on 2026-08-06:

- Al Quran Cloud API documentation: <https://alquran.cloud/api>
- Al Quran Cloud terms, last updated 2026-06-14: <https://alquran.cloud/terms-and-conditions>
- Tanzil text license: <https://tanzil.net/docs/Text_License>
- Tanzil download/version page: <https://tanzil.net/download/>
- Tanzil Uthmani description: <https://tanzil.net/docs/uthmani>
- Tanzil Medina Mushaf description: <https://tanzil.net/docs/medina_mushaf>

Al Quran Cloud's terms permit reproduction, storage, and display of the Arabic text, request source
acknowledgement, and require faithful preservation of Uthmani orthography and diacritics. The same
terms describe historical/global sourcing and say current Arabic text comes from various sources,
including Tanzil.net and Quran Academy. They do **not** map `quran-uthmani` to one exact upstream
artifact or version. Therefore the evidence supports Al Quran Cloud as the direct acquisition
provider, but it does not support claiming that these exact bytes are definitively the Tanzil
artifact.

If a future source audit proves that exact upstream chain, Tanzil's CC BY 3.0 attribution, source
link, notice, and verbatim-copy obligations also apply. Until then, recording Tanzil as the direct
source would be false precision.

## Accepted migration decision

1. The full-corpus source id is **`alquran-cloud`**, with provider URL
   `https://alquran.cloud/api`, edition `quran-uthmani`, and the existing import version
   `full-quran-2026-06-26`.
2. `tanzil` remains a valid identity for the historical Fatihah fixture and any separately proven
   Tanzil import; it is not an alias for this full corpus.
3. The original adjacent import manifest and 114 Surah files remain untouched as historical,
   checksum-validated acquisition material.
4. Additive database migration `0028_canonical_quran_source_id.sql` expands the canonical source
   check without rewriting the historical `0001` migration.
5. Fresh full-corpus seeds use `alquran-cloud`. Existing environments must regenerate/reseed the
   canonical bundle through the normal full-corpus seed path; they must not relabel rows while
   retaining old source-bound checksums.
6. This task changes source metadata and therefore source-bound record checksums. It changes no
   `ayah.text` or `word.text` bytes. Automated proof compares old/new source bundles byte-for-byte.
7. The precise word-token serialization hash is intentionally deferred to W1.2; W1.1 does not
   silently absorb that separately approved task.

## Residual risk

The exact edition-level upstream artifact and upstream license chain remain unresolved because the
direct provider does not publish that mapping. Production attribution must name Al Quran Cloud and
must not market the corpus as a verified Tanzil release unless new primary evidence closes this gap.
