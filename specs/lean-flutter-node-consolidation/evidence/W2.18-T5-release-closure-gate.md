## What is now enforced

- Release mode accepts only one candidate-bound evidence chain covering the exact image proof,
  classroom/burst/soak artifacts, signed monitoring observation, healthy controller decision,
  deliberate rollback drill, and the fixed remote required-check set.
- The monitoring and remote-CI documents must be signed by active Ed25519 attestors in a strict,
  public-only trust policy. Evidence is fresh, temporally ordered, hash-bound, and immutable.
- Promotion requires three fresh approvals from distinct release-owner, security, and SRE keys.
  Reused keys, revoked keys, altered bytes, missing checks, stale evidence, incident-only rollback,
  mismatched candidate identity, and non-monotonic timestamps fail closed.
- A healthy controller can only report `awaiting-human-promotion`; it cannot move traffic. The
  deliberate drill must prove reversal, all six previous application images, one stored effect,
  zero duplicate effects, and successful privacy cleanup.
- `scripts/verify.sh --release` validates the external chain before release work and writes the
  create-only closure artifact only after every release check succeeds. The closure status is
  `ready-for-manual-promotion`; no script can manufacture a human approval or promote traffic.
