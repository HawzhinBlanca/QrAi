# W2.13 evidence — bounded graceful shutdown and resource drain

**Status:** complete; local and exact-candidate remote proof are green<br>

**Scope:** approved W2.13<br>
**Criterion:** BE-5

## Implemented

- SIGINT and SIGTERM now enter one idempotent shutdown controller: stop admission, preserve
  completing HTTP requests, drain tracked HTTP and upgraded sockets, then close resources.
- The strict `SHUTDOWN_GRACE_SECS` setting accepts only whole seconds from 1 through 300. Eighty
  percent of the budget is reserved for traffic drain and the final twenty percent for resource
  teardown; a referenced hard-deadline timer prevents an indefinite process hang.
- Requests, raw connections, and protocol-upgraded sockets are tracked before route handlers run.
  Repeated signals escalate the existing shutdown rather than starting duplicate cleanup.
- Fastify is configured with `return503OnClosing: true` and `forceCloseConnections: false`; the
  controller performs its own timed force-close, while Postgres.js receives the bounded final
  resource-close budget.
- The production image declares `STOPSIGNAL SIGTERM`; Compose keeps its outer stop grace longer
  than the application grace and exposes both operational defaults.
- Fixed operational events identify shutdown start, forced connection closure, resource closure,
  completion, and hard-deadline failure without emitting requests, audio, credentials, or secrets.

## Fastify compatibility finding

The red child-process test exposed a pinned Fastify 5.11 behavior: its native close branch treats
the documented `forceCloseConnections: "idle"` value as truthy and calls `closeAllConnections`,
terminating active requests. W2.13 therefore pins `false`; Node 22 closes idle keep-alive sockets,
and the tested application controller owns the bounded force phase. This is an evidence-based
compatibility choice, not an assumed framework guarantee.
