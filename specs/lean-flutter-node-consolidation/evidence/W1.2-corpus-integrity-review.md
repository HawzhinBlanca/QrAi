# W1.2 corpus integrity review

**Reviewed:** 2026-08-06<br>
**Scope:** the shipped `quran-uthmani` ayah strings and their parallel ordered word-token arrays.<br>
**Decision:** add `provenance-v2.json`; keep the 114 source files, `provenance-v1.json`, and the legacy delimiter checksum immutable.

## Framing

- Algorithm: SHA-256 over UTF-8 bytes exactly as shipped; no trimming or Unicode normalization.
- Every field is framed as its unsigned 64-bit big-endian byte length followed by its bytes.
- Every record is framed again as its unsigned 64-bit big-endian payload length followed by its framed fields.
- The framed domain is hashed first: `qrai.full-quran.ayahs.v1` or `qrai.full-quran.word-tokens.v1`.
- Ayah fields: decimal `surahNumber`, decimal `ayahNumber`, exact `text`.
- Token fields: decimal `surahNumber`, decimal `ayahNumber`, decimal one-based `wordIndex`, exact token `text`.
- Order: surah, ayah, then word index ascending.

## Reviewed results

- Ayahs: 6,236; SHA-256 `be19912bd87d3a8ad941ab458e5c4e167e49b3749fab704526a2f1430f532fbb`.
- Word tokens: 82,456; SHA-256 `580276af15ecb4756b8a02afb922e33867f06faf77482ac6c5b393fc729e23a4`.
- Joining stored tokens with one U+0020 reconstructs 6,235 ayahs exactly.
- Ayah 1:1 is the sole declared exception: its ayah text preserves a leading U+FEFF that is not a token.
- A same-count token mutation changes the token hash while leaving the ayah hash and counts unchanged.

## Seed decision

The production SQL generator must validate source, edition, import version, counts, reconstruction contract, v1 checksum pin, and both v2 hashes before writing its first SQL byte. Existing per-row checksums and database columns remain unchanged.
