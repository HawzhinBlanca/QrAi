# W2.10 evidence — ordered production boundary middleware

Date: 2026-08-07

## Delivered boundary

- The global Node HTTP order is now executable and tested: CORS/preflight → maintenance → bounded
  rate admission → body parser/route authorization/handler → fixed error shaping → response metrics.
- Maintenance returns fixed `503 {"error":"service is in maintenance"}` and exempts only exact
  `/health`, `/ready`, and `/metrics`. Blocked work spends no token and reaches no auth/handler.
- Default-on admission is a dependency-free per-process token bucket: capacity 200, one token per
  50 ms, at most 10,000 client buckets, ten-minute idle eviction, then LRU eviction. It creates no
  per-key timer and makes no authorization decision.
- Forwarded IP headers are ignored by default. `TRUST_PROXY_HEADERS=1|true` enables an explicit
  positive `TRUST_PROXY_HOPS` count (default one, maximum 32); invalid or inert configurations exit
  before listen.
- The existing 2 MiB global and 16 MiB ASR body ceilings, bearer/cookie/header auth order,
  secret-safe Fastify request logs, NUL mapping, metrics, and learner/tenant gates remain intact.
- Error shaping was hardened after a new red test found that an arbitrary exception carrying a
  `statusCode` could expose its message. Only fixed 413/415 Fastify parser errors are now public;
  every arbitrary status-bearing exception receives the fixed generic 500.

No broker, cache, service, runtime package, table, migration, or login surface was added.

message bypass before it was closed.
