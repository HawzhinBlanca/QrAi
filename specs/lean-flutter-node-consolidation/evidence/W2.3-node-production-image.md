## Implemented image/topology

- `server/Dockerfile` is multi-stage and pins the official Node 22.13.1 Bookworm-slim OCI index to
  `sha256:83fdfa2a4de32d7f8d79829ea259bd6a4821f8b2d123204ac467fbe3966450fc`.
- The disposable builder uses pnpm 11.7.0 and Corepack 0.34.5, the newest registry release whose
  engine range supports Node 22.13.1. The older bundled Corepack failed pnpm's rotated signing key;
  Corepack 0.35.0 was rejected because its engine floor is Node 22.22.2.
- `pnpm deploy --legacy --prod` materializes only the server production graph. Runtime contains the
  five declared libraries, server runtime files, legacy Node route modules, and the exact ML
  attribution/alignment/provenance files imported by that transitional boundary.
- Runtime is `NODE_ENV=production`, `USER node`, with no TypeScript, tests, apps, contracts package,
  Rust API, or broad Quran source tree.
- `server/src/container-healthcheck.mjs` uses native `fetch` and `AbortSignal.timeout`, consumes no
  response body or error detail, and fails closed.
- Compose `node-api` exposes port 8082 only to the internal network, serves `/health` and `/ready`
  locally, retains Rust as compatibility upstream, and has no Web or realtime traffic dependency.
- Release image, build evidence, signed manifest, smoke evidence, licence, SBOM, and Docker workflow
  inventories now include `node-api`.
