# W1.9 — Tajweed instruction/performance boundary

Date: 2026-08-07
Scope: engineering correctness and reliability proof. This slice does not claim that an acoustic
Tajweed evaluator exists or that learner-performance quality has been measured.

## Result

Deterministic Quran-text rules are now instructional annotations, not findings about a learner.
The producer returns them in `annotations[]` with `analysisBasis='text-rule'`,
`instructional=true`, and sources. It omits confidence, severity, and review state. `findings[]` is
reserved for span-linked acoustic judgments and remains empty until W1.10 supplies a real acoustic
producer.

Rust and Node validate this disjoint envelope before using it. They reject text rules in
`findings[]`, acoustic items in `annotations[]`, and annotations carrying performance fields. Only
validated acoustic findings can enter `tajweed_findings`, teacher review, session feedback, or the
learner gate. The Flutter and web models require `analysisBasis='acoustic'` for a performance
finding. The agents runtime now mirrors the same refusal, closing the final shared-gate bypass found
by the canonical run.

Migration 0030 reclassifies historical `canonical-text` rows as `text-rule`, replaces their
placeholder confidence with null, and enforces the database invariant:

- text-rule implies null confidence;
- acoustic implies non-null confidence;
- review queues and learner-performance reads include acoustic rows only;
- accepting a text rule as learner-performance feedback is refused.

The migration was applied to the local canonical database: one new migration applied, 29 total.
No historical row was deleted.
