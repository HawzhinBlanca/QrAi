## What is now implemented

- Prometheus scrapes the Node API, durable worker, Rust platform API, and realtime gateway using a
  mounted metrics-token secret. Ten low-cardinality rules cover readiness, HTTP error/latency,
  fallback share, job backlog/retry/dead-letter, and unindexed audio without learner, tenant, trace,
  or credential labels.
- The Grafana dashboard separates Node request/error/latency/fallback signals, durable-job state,
  lost-audio state, and the four service readiness signals.
- The k6 program has three closed candidate-bound profiles: classroom (10 requests/s for 5 minutes),
  burst (ramp to 50 requests/s for 2 minutes), and soak (5 requests/s for 30 minutes). Promotion
  accepts only write-once, fresh, identity-matched artifacts that honestly derive every threshold
  result from the measured metrics.
- The controller has a closed observation schema and immutable stop limits. Any readiness, SLO,
  job, privacy, tenant-isolation, chunk-loss, or learner-feedback stop signal first reverses Web and
  gateway routing together, then deploys the six previous application images with `--pull never`,
  then verifies those running images and a real write/privacy-cleanup effect probe.
- A healthy observation returns `awaiting-human-promotion` and performs no promotion mutation.
  Rollback completion requires all six previous application images, zero duplicate effects, and
  privacy cleanup. Failed reversal, previous deployment, or previous verification remains failed
  evidence and cannot be rewritten as success.
- `release-deployment verify --scope application` verifies only the six long-running application
  images, deliberately excluding the one-shot migration runner from rollback health claims.
