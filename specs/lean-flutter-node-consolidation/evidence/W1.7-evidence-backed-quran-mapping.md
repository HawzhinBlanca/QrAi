## Result

Quran-constrained alignment now carries only measured recognized-token spans into canonical
matched/misread results. Missed canonical words receive `null` spans, and repeated or weak extra
recognized words retain only their own source spans. Canonical Quran bytes are neither trimmed nor
normalized.

The ML alignment response explicitly states whether it is finalizable. Text-only recognition remains
available as non-finalized practice output, while malformed, incomplete, or inconsistent token
evidence fails closed with no partial alignment claim. Public Rust and Node proxy routes reject
client-supplied `recognizedTokens`; the trusted tokens can enter only through the server-to-server
session-transcript path.

Rust finalization now forwards those tokens instead of a bare recognized-text array, accepts only a
producer response marked finalizable, and persists only canonical `matched`/`misread` rows carrying
usable measured spans. A miss, extra, needs-review result, unknown canonical word, or unusable span
rolls the whole alignment replacement transaction back, preserving the earlier rows.
