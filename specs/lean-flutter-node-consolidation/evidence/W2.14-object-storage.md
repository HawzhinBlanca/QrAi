**Criterion:** BE-6

## Implemented

- The Node backend and ML compatibility service now share one strict retained-audio object-store
  contract with private S3-compatible production and filesystem-only test/development adapters.
- Every current object key is server-derived as
  `audio/v1/<tenant>/<learner>/<session>/<chunk>.pcm`; tenant, learner, session, chunk, retention,
  spans, sample rate, byte length, and checksum are validated rather than accepted as caller
  authority.
- Writes are create-only and retry-safe. Identical retries are no-ops, conflicting bytes or
  metadata are refused, reads verify bounded length and SHA-256 integrity, and deletes are
  idempotent and absence-verified.
- S3 writes use conditional creation, checksum metadata, private bucket policy assumptions, full
  list pagination, bounded batched deletion, per-key error handling, readiness, cancellation, and
  body-stream abort handling. Production-shaped configuration fails closed instead of silently
  selecting the filesystem.
- Node review playback and privacy export/delete use the injected store directly. Review remains
  tenant/role/consent gated and is recorded as served only after a complete valid read. Privacy
  deletion preserves database state if storage deletion fails and remains retry-safe.
- Audio indexing in both Node and the Rust compatibility oracle derives the v1 object key from
  verified session authority. The realtime gateway no longer supplies an authoritative object
  key.
- The reconciliation command is storage-neutral, dry-run first, ownership checked, current/S3 and
  declared legacy-filesystem aware, and reports both stored-without-index and indexed-without-object
  states without inventing a successful repair.
- Container, Compose, backup/restore, staging, inventory, architecture, testing, decisions, and
  threat-model documentation now state the production object-storage boundary and its remaining
  operational obligations.
