## Implemented boundary

- Added exactly three handlers: invitation exchange, credential refresh, and current-session
  DELETE. There is no identity creation or fourth authentication API.
- Added strict `DEVICE_IDENTITY_ENABLED` parsing: only literal `1` enables registration; unset/`0`
  stays off and malformed values terminate startup. Direct composition accepts only a boolean.
- Kept the default standalone surface at 41 registered operations. The registry declares 44, but
  marks the three device entries with `ownerGate: "device-identity"`; disabled requests are local
  404s and cutover/parity accounting excludes dormant entries.
- Exchange accepts only `invitationToken`; refresh accepts only `refreshToken`; neither accepts
  tenant, user, role, session, or lifetime. DELETE accepts only the reserved device access Bearer.
- Promoted only these three manifest entries to `implemented-owner-gated`. Added strict OpenAPI 3.1
  request/response schemas with no undeclared properties and an explicit owner-gate annotation.
- Preserved the 42-operation Rust baseline, login-off default, password/pilot compatibility, and
  the existing 41-route default Node behavior.
