# W2.8 evidence — learner-owned recitation history

Date: 2026-08-07

## Delivered boundary

- `GET /v1/learner/recitation-sessions` is an explicit ADR-0038 Node target addition, separate
  from the tenant-wide teacher/admin/ops session list.
- The route is learner-only and returns only the authenticated learner's own tenant-scoped
  sessions, ordered by exact `(started_at DESC, id DESC)` keyset pagination.
- Each history row reports acoustic finding state counts only. It exposes no learner id, tenant id,
  tajweed judgement, confidence, explanation, or source; detailed feedback remains governed by the
  W2.7 review/evidence redaction gate.
- Cursor lookup is owner- and tenant-scoped. Unknown, other-owner, and cross-tenant cursors all
  return 404. `limit` is strict, integer-only, and bounded to `[1,50]` with a default of 20.
- The immutable Rust baseline remains 42 operations. The active transition contract is derived as
  that baseline plus manifest-classified implemented Node additions, currently 43 operations.
- No service, migration, table, queue, model, or duplicate learner-feedback policy was added.

## Red proof

Before implementation, the contract suite failed because learner history was still classified
`planned`, and the route registries remained at 40. Forcing the route local then failed shell startup:

```text
NODE_API_PORTED names an unportable route: GET /v1/learner/recitation-sessions
```

The first full gate exposed one additional hard-coded transition assumption: the older coverage
guard required OpenAPI to equal only the 42-route Rust baseline. It was tightened to require the
baseline plus only manifest-classified implemented additions, and to prove every implemented
addition exists in the executable Node route table.
