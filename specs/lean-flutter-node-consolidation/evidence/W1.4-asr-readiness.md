# W1.4 ASR readiness evidence

Date: 2026-08-06<br>
Scope: QA-8 and the ASR slice of OP-4; whole-system deep readiness remains W6.3.

## Result

ASR liveness and readiness are separate. FastAPI binds and `/health` answers from process state
while one background worker loads the selected model. `/ready` and ASR-backed route admission stay
closed until the configured digest matches the producer-resolved digest and a bounded known-audio
inference probe returns a structurally valid result.

The probe input is a declared 100 ms, 16 kHz mono PCM zero-signal WAV. Its exact SHA-256 is
`2976da01e205a110c9fa41d47659e238a5c6d3c3f3137582f2949853faa201dd`. It contains no learner
audio, and neither its transcript nor its latency is model-quality evidence.

## Focused proof

- Eight failing-first readiness tests cover loading, one-worker ownership, transient load recovery,
  missing/wrong digest refusal, terminal no-reload behavior, transient probe recovery, probe
  timeout without overlap, exact fixture bytes, and production wiring.
- A real local FastAPI run with Whisper `base` resolved artifact digest
  `sha256:ed3a0b6b1c0edf879ad9b11b1af5a0e6ab5db9205f891f668f8b0e6c6326e34e` and completed the
  synthetic inference probe in 5,331 ms before `/ready` returned 200.
- The same real service with a deliberately wrong configured digest returned `/health` 200 and
  `/ready` 503 with safe reason `model-digest-mismatch`; the response exposed no exception.
- The production image with the correct `base` digest kept `/health` at 200 while `/ready` moved
  from 503 (`known-audio-probe-running`) to 200. With the shipped 60-second deadline, two clean
  container runs completed the real probe in 33,953 ms and 33,270 ms respectively.
- The same image with a wrong digest returned `/ready` 503 at attempt 1 before and after a
  five-second hold, proving terminal configuration refusal without a reload storm. The response
  reported the independently resolved artifact digest, not the configured false value.
- The same image with an invalid model stayed live, returned `model-load-failed`, and advanced from
  attempt 5 to attempt 6 after the configured retry interval. Replacing an unready container with
  the correctly pinned image recovered from 503 to 200.
- All disposable proof containers were stopped after the checks. The local ARM64 production image
  measured 3,411,630,939 bytes. Its locked Python dependency graph currently pulls large CUDA-era
  packages into a CPU image; this is explicit W1.5 capacity/packaging debt, not readiness success.
