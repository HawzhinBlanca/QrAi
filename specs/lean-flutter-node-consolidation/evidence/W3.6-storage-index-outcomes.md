## Red-first and audit evidence

- The first migration proof failed at the expected old boundary: the plan still contained 35
  migrations instead of 36 and Postgres had no `realtime_audio_chunk_outcomes` relation.
- The first runtime proof failed because `server/src/realtime/outcomes.mjs` did not exist. The Node
  consumer could report only store-attempt metrics; it had no durable accepted-loss or
  stored-unindexed authority and no direct path from retained storage to the playback index.
- The first finalization union proof produced 2 instead of 3 missing chunks because it knew only
  inference gaps and could not include the durable realtime tail.
- The first live restricted-database batch proof exposed invalid generated bulk SQL at
  `tenant_id`. The diagnostic insert was corrected and then exercised through the real restricted
  application role rather than replaced by a fake.
- Final pre-commit review found a cross-path aggregate hazard: recomputing `lost_chunk_count` only
  from realtime rows during repair could erase unrelated inference gaps. The implementation now
  applies idempotent insert/repair deltas, rejects a retry that changes its reason, and a live test
  pins preservation of unrelated gaps across repeated repair.

## Implemented boundary

- Additive migration 0037 creates one checksum-locked, forced-RLS, session-cascaded diagnostic
  table. It accepts only constrained `accepted-lost` and `stored-unindexed` states with fixed reason
  codes and timestamps. It contains no audio bytes, credentials, nonce, trace, object key, learner
  display data, exception, URL, or arbitrary error text.
- `server/src/storage/audio-index.mjs` is the single indexing domain for the signed-ticket HTTP
  adapter, the realtime consumer, and repair. It verifies current tenant/session learner and
  retention authority, derives the canonical private object key, validates spans/rates, treats an
  exact retry as success, and refuses immutable conflicts.
- `server/src/realtime/outcomes.mjs` keeps enqueue acknowledgement distinct from storage and index
  completion. Retained success creates the playback index; discard creates none; storage or index
  failure has a fixed durable/unrecorded outcome and closes the socket instead of claiming delivery.
  Rejected pre-enqueue frames never consume sequence or create accepted-chunk state.
- Shutdown classifies both in-flight and queued accepted chunks through the bounded outcome batch.
  Finalization unions unrepaired accepted-loss identities with inference-reported gaps without
  double counting. Repair changes only its own aggregate delta, so other evidence is preserved.
- The dry-run-first repair command now uses the shared restricted tenant boundary. Apply mode
  rechecks object integrity, learner ownership, current retention, canonical identity and index
  metadata, then commits the playback index and repaired provenance atomically. A conditional write
  that committed remotely after a timeout can therefore be recovered honestly.
- `audio_chunks` remains the sole playback authority. The diagnostic table cannot make audio
  learner- or teacher-visible. Rust remains the sole public realtime traffic target.
