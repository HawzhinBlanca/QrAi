# W2.15 T3 evidence — durable domain workflows

Date: 2026-08-07

## Implemented

- Finalization now authorizes and captures a server-derived evidence snapshot, enqueues one durable
  intent, performs transcript/alignment work outside a database transaction, and commits through
  the existing destructive alignment writer together with fenced job completion.
- Session Tajweed evaluation persists only the closed server-authoritative consent/session/span
  envelope, preserves learner redaction and offline release-evidence authority, and commits through
  the existing finding writer. It adds no `eval_runs` producer or signing path.
- Privacy export/delete now captures a bounded manifest and durable audit intent before deletion.
  Object deletion remains retry-idempotent; the manifest, privacy ledger, domain cascade, response,
  and job completion are fenced so a crash cannot lose the accepted erasure receipt.
- Concurrent identical calls wait for one lease and return its exact stored response. Responses are
  validated structurally then stored as serialized JSON because PostgreSQL `jsonb` canonicalizes
  object order; this preserves the existing Rust-compatible declaration order recursively.
- API composition creates one store/runtime from the existing database and service/storage
  boundaries. No broker, second backend package, public job endpoint, raw audio, transcript, URL,
  credential, or unbounded caller document was added.
