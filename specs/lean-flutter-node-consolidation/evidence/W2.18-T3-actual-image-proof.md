## What is now implemented

- `retained-canary` mode alone emits `x-qrai-route-owner: node-local|rust-compatibility`; ordinary
  standalone and compatibility responses do not gain the proof header.
- `scripts/lib/http-canary-probe.mjs` derives the exact 39 retained routes from the checked manifest,
  pins the four Rust transition routes, drives hostile inputs, uses short-lived HS256 JWT actors,
  and commits a real session/ticket/audio-index effect through the candidate HTTP boundary.
- `scripts/lib/http-canary-image.mjs` accepts only live-candidate, immutable-Compose evidence bound to
  a clean matching source SHA, candidate and previous manifests, exact rendered topology, seven
  inspected service/container identities, exact ordered proof stages, command/output hashes, and a
  maximum 24-hour lifetime. Dirty, expired, fixture, source-process, wrong-route, wrong-image,
  wrong-topology, incomplete, or Rust-fallback evidence fails closed.
- `scripts/http-canary-image.mjs` inspects the already-running release/canary stack and never builds
  or starts a source checkout server. It runs JWT-authenticated effect/privacy/tenant smoke, hostile
  probes, direct durable audio indexing, and the real gateway smoke. It deliberately stops Rust,
  requires all retained routes to stay Node-local and all transition routes to fail with 502, then
  restores and rechecks Rust. Output uses create-only file semantics; a failed run cannot overwrite
  itself with a later pass.
- The operator path requires an explicit disposable-database acknowledgement and is documented in
  the staging runbook. It does not enable development header authentication and never emits tokens
  or secret values into evidence.
