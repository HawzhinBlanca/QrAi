# W2.11 evidence — restricted database and tenant transaction boundary

**Date:** 2026-08-07<br>
**Scope:** approved W2.11<br>
**Criterion:** DB-2

## Implemented

- The one Node database primitive now inspects the effective Postgres role and rejects
  `SUPERUSER`, `BYPASSRLS`, `CREATEDB`, `CREATEROLE`, and `REPLICATION` capabilities.
- Fastify runs that assertion in `onReady`, before `listen` can complete, and closes the pool in
  `onClose`.
- The established `ALLOW_SUPERUSER_DB_ROLE` plus deprecated local alias is the only explicit
  development relaxation; production remains fail-closed.
- Pilot bootstrap now uses `withDiscoveredTenant`. The security-definer invitation consume happens
  before tenant identity exists; tenant-owned work cannot run until the same transaction-local GUC
  and 10-second statement timeout used by `withTenant` are installed.
- A hermetic architecture gate pins the sole runtime driver owner, the three operator-script owners,
  the exact raw SQL allowlist, and the ban on route-owned transactions/tenant GUC setup.
